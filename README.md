| File | Key functions | Registers touched | What actually happens |
|---|---|---|---|
| `REGISTER_ENUMS.hpp` | — | — | Just two `enum class`es (`AENUM{A..F}`, `DENUM{R0..R12}`) so a register can be passed around as an ordinary C++ value (e.g. into a `switch`) — the real `AREG`/`DREG` hardware types can't be used that way. No chip state touched. |
| `MISC_FUNCTIONS.hpp` / `.cpp` | `shift_R11(x,y)` | `R11` (in/out), `R9` (scratch) | Shifts a digital image in `R11` by `(x,y)` pixels via repeated single-pixel neighbor reads (`DNEWS0(R9,R11); DNEWS0(R11,R9)` — bounces through a scratch register once per pixel of shift distance, boundary reads as 0). |
| | `load_rect_into_DREG` / `load_centered_rect_into_DREG` | any `R0`–`R12` (picked via a `switch` on the `DENUM` param) | Wraps `scamp5_load_rect(reg,...)`, which paints a filled rectangle of 1s into the given digital register — a mask, not an image. |
| | `load_DREG_into_F(reg, white, black)` | reads any digital reg; writes `F` | `F := black` everywhere (`scamp5_load_in`+`mov`), then `F := white` wherever `reg == 1` (`WHERE(reg); mov(F,IN)`). Turns a 0/1 mask into a real two-level analog image. |
| `AREG_POOLING.hpp` / `.cpp` | `MAX_POOL_F(iterations, dirx, diry, blocking)` | `F` (in/out), `E` (shifted copy), `R0` (compare-flag scratch), `R10` (block-boundary mask, `blocking` pass only) | Per iteration: `bus(NEWS,F); bus(E,XS or XN)` copies `F` shifted one row into `E`; `sub(F,F,E)` then `where(F)` finds where the *original* was bigger and adds `E` back to restore it, while `NOT(R0,FLAG); WHERE(R0); mov(F,E)` overwrites the rest with the (bigger) neighbor value — net effect: `F := max(F, shifted F)`. Do this 3× vertically then 3× horizontally = every pixel now holds the max of its surrounding 4×4 block. The `blocking` pass afterward uses `R10` + `DNEWS(R10,FLAG,east/south)` to broadcast that corner value to fill the whole 4×4 cell uniformly. |
| `IMG_SCALING_DIGITAL.hpp` / `.cpp` | `STEP_SCALE_UP_R11` / `STEP_SCALE_DOWN_R11(step)` | `R11` (image, in/out), `R12` (working copy), `R0` (mask, via `SET`), `R1`–`R4` (temporary boundary-region rectangles built with `scamp5_load_rect`) | Looks up a per-step magnitude `i = scaling_rowcol_order[step]` (an 88-entry empirically-tuned table), builds row/column boundary masks with it, and does a masked `DNEWS0(R11,R12)` neighbor-read so pixels near one edge get "pulled toward" or "pushed away from" center by one increment. Repeated calls compound into a smooth grow/shrink. Digital (not analog) specifically because repeated *analog* copies pick up noise every hop — a binary value survives unlimited copies untouched (paper Section 4.5). |
| | `SCALE(reg, magnitude, scale_down)` | (delegates to the above) | Just runs `magnitude` of those single steps in a row — the "coarse" jump. **This is where a real bug lived** (see `GESTURE_CAPTURE.cpp` below): calling it with a negative magnitude silently no-ops because the internal loop is `for (unsigned char n=0; n<scaling_mag; n++)`. |
| `IMG_TF.hpp` | — | — | Just forward-declares unrelated math helpers (`sin_approx3` etc.) pulled in by `IMG_SCALING_DIGITAL`'s include chain. Unused here. |
| `GESTURE_CAPTURE.hpp` / `.cpp` | `extract_gesture_blob_from_F_into_R11(...)` | `F` (in: camera frame), `E` (scratch: holds the threshold constant), `R11` (out: binary hand silhouette) | `scamp5_load_in(E,threshold); sub(F,F,E)` subtracts the threshold from every pixel; `where(F); MOV(R11,FLAG)` sets `R11=1` wherever the result is still positive (bright hand pixels). `scamp5_scan_boundingbox(R11,...)` reads back the silhouette's bounding box to the M0 controller (ordinary `uint8_t[4]`, off-chip-register at this point) so plain C++ can compute a center offset and required scale factor. |
| | (same fn, continued) | `R11` via `shift_R11`, then `SCALE`/`STEP_SCALE_*_R11` | Re-centers the blob (`MISC_FUNCTIONS::shift_R11`), then grows/shrinks it to fill a `size×size` box using the `IMG_SCALING_DIGITAL` routines above — with the direction/magnitude bug fixed (computes `scale_down` correctly and clamps the coarse magnitude to the table's 88-entry bound) and a `box_w/box_h <= 0` early-return guard for when nothing is above threshold. |
| | `duplicate_gesture_into_grid_R10(cell_size, grid_size, padding)` | `R10` (out: tiled grid), `R11` (in: silhouette), `R9` (shift scratch), `R1`–`R4` (OR-accumulation scratch), then `E`/`F` (analog cleanup pass) | Digital phase: `MOV(R10,R11)` seeds the grid with one copy, then for each of `grid_size-1` more copies: shift `R11` by one cell-width via repeated `DNEWS0(R9,R11); DNEWS0(R11,R9)`, `REFRESH(R11)` (digital registers decay over time and need periodic refreshing), then `OR(R2,R10,R11); MOV(R10,R2)` merges it in. Analog phase (comment preserved from the original author: *"DO THE SECOND PART IN AREG SINCE THE DREG ON MY SCAMP ARE BAD"*) — a 7-iteration `add`/`sub`/`where`/`OR` patch using `E`/`F` that cleans up a known hardware quirk in how the digital duplication decays. |
| `FUNCS_WEIGHT_LOADING.hpp` | `load_filter_weights_into_grid_F(...)` | `F` (out: accumulates the burned-in conv weights), `R1` (per-block rectangle mask), `R2` (per-tap checkerboard pattern via `scamp5_load_pattern`), `R3` (`AND(R1,R2)` = exact pixels for this filter+tap) | For each of the 16 filters and each of its 16 taps: if the trained weight is `+1`, `WHERE(R3); add(F,F,IN)`; if `-1`, `sub(F,F,IN)`; if `0`, skip entirely (no instruction). Runs once at setup (button press), not per-frame — by the end, `F` physically encodes all 16 filters, each living in its own 64×64 block. |
| | `load_checkerboard_grid_R10(...)` | `R10` (out, built via repeated `OR`), `R11` (per-block scratch) | Builds the alternating-block checkerboard mask itself (only blocks where `(gridy%2==gridx%2)` get OR'd in) — this is the pattern that lets the convolution step later know "which blocks currently hold a valid weight replica." |
| | `load_FC_weights_into_grid_E(...)` | `R1` (+1-weight mask, OR-accumulated), `R2` (-1-weight mask, OR-accumulated), `R11` (single-pixel scratch via `scamp5_load_point`), `E` (out) | For every (neuron, filter, pooled x, y) with a nonzero trained FC weight, sets one pixel into `R1` or `R2` depending on sign. At the end, `E := (IN=120 wherever R1) + (-IN wherever R2)` bakes the entire 20,480-weight FC layer into one analog image in a single pass. |
| `WEIGHTS_GESTURE_4x4_16CONVOLS_64x64INPUT.hpp` | — | — | Pure generated data (no chip operations) — produced by `train.py`. `NUM_GESTURES`/`NUM_FILTERS`/etc. constants, gesture name strings, the `[16][1][16]` ternary conv array, and the flat `[20480]` ternary FC array, in the exact index order the loader functions above expect. Regenerate by retraining. |
| `MAIN_GESTURE_SINGLE_LAYER_16.cpp` | weight-load button handler | `E` (built by `load_FC_weights_into_grid_E`) → `A`; `F` (built by `load_filter_weights_into_grid_F`) → `B` | One-time (on button click): copies the freshly-built FC weight image from `E` into `A`, and the freshly-built conv weight image from `F` into `B` — `A`/`B` are the *persistent* homes for the two weight sets for the rest of the session. |
| | per-frame capture | `F`/`E` ← `scamp5_get_image`; `R11`/`R10` via `GESTURE_CAPTURE`; `R5 := MOV(R5,R10)` | Captures a frame, extracts+tiles the hand silhouette (delegates to `GESTURE_CAPTURE.cpp`), and stashes the tiled result in `R5` (kept separate from `R10` since `R10` gets reused as scratch almost immediately after). |
| | weight "refresh" | `A` and `B` (in place), using `F`/`E` as scratch | Analog registers slowly decay/drift over time. This block re-snaps `A` (and separately `B`) back toward whichever of two reference levels (`50`/`-50` for `A`, `80`/`-80` for `B`) they're already closest to — effectively a digital-like "re-quantize toward the nearest expected value" every single frame, so weight precision doesn't erode over a long-running session. |
| | **convolution layer** | `R9` = sign mask of `B` (via `D`); `R8` = the tiled image (from `R5`); `C` = accumulator; `R1`/`R2`/`R3`/`R10`/`R11` = per-tap scratch masks | For each of the 16 taps (4×4 kernel): `scamp5_load_pattern(R11,...)` marks that tap's position within each block; `AND(R1,R9,R11)` restricts to blocks whose weight-sign at that position is actually set; `scamp5_flood(R11,R10,0,1)` — the checkerboard trick — spreads that single tap-position flag across its *entire* 64×64 block (constrained by the `R10` block-boundary mask), so every pixel in a block "knows" this tap's sign for its own filter. Then `AND(R1,R8,R11); WHERE(R1); add(C,C,F)` adds the (constant `input_white`-valued) input wherever weight is `+1`, and the `NOT(R1,R11)`/`AND(R2,...)`/`sub(C,C,F)` pair subtracts wherever it's `-1`. `R8` is then shifted one pixel (`DNEWS(R8,FLAG,west)`, wrapping east×3+south at row ends) so the *next* tap sees the correctly-offset image. All 16 filters' worth of this happens in the same pass because they live in different blocks simultaneously — nothing here is a per-filter loop over the whole array, only a per-tap loop. |
| | **ReLU** | `C` (in place), `F` (scratch) | `where(C); mov(F,C); all(); mov(C,F)` — `F` starts at 0 (`load_in(F,0)`), gets overwritten with `C`'s value only where `C>0`, then copied back into `C`. Net: negative values become exactly zero, positive values are untouched. No division, no calibrated threshold — literally "if negative, clear." |
| | **max pool** | `C`→`F`→`AREG_POOLING::MAX_POOL_F`→`F`→`C`, then `movx(C,C,west/north)` | Delegates to `AREG_POOLING.cpp` (above), then re-aligns the pooled values to a canonical corner of each 4×4 cell. |
| | **FC layer setup** | `R6` = +1 mask of `A`, `R7` = -1 mask of `A` (via `F`), `REFRESH(R6);REFRESH(R7)` | Same "extract the sign" trick used for the conv weights, but on `A` (the FC weights) instead of `B`. `R6`/`R7` get explicitly refreshed since they're read many times in the loop below within the same frame. |
| | **FC layer readout** | `F` (accumulator) ← `WHERE(R6) add(F,F,C)` / `WHERE(R7) sub(F,F,C)`; `E := F`; `scamp5_global_sum_sparse(E, ...)` | Builds "pooled activation × ternary FC weight" for every one of the 4096 connections per neuron in one masked add/sub pass, then reads out a single neuron's score via a hardware global-sum instruction over a strided sparse grid of pixel addresses. Repeated over 4 quadrants (the array holds 4 identical duplicated copies of everything, purely for noise-averaging — not 4 different neurons) × a `tweak`-controlled number of repeats, accumulated into a plain `int sums[5]` C++ array — at this point we're off the chip entirely, back on the M0 controller doing ordinary arithmetic. |
| | prediction | *(no chip registers — plain C++ on the M0 core)* | Min-max normalizes the 5 raw sums to a 0–100 bar-graph scale (so the winning gesture is always drawn "capped" at 100 — that's a display artifact, not a confidence value), averages over the last 3 frames to reduce flicker, and prints `pred: <gesture>` via `vs_post_text`. |
| `scamp5_main.cpp` | `main()`, `scamp5_main()` | — | Pure boilerplate: binds the USB I/O agent, wires up two generic sliders (frame rate, chip voltage), then calls `MAIN_GESTURE_SINGLE_LAYER_16()`, which never returns. No pipeline logic lives here. |
